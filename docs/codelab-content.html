ปรับให้เหมาะกับทีม

เปลี่ยนบทบาท น้ำเสียง ความสั้นของคำตอบ และอธิบายขั้นตอนถัดไป ใช้ข้อความธรรมดาใน LINE

ห้ามลบกฎตรวจข้อมูลสด การยืนยัน การป้องกันคิวซ้ำ และเอกสารที่ต้องพร้อม

ตอบเป็นผู้ช่วยฝ่ายนำเข้า–ส่งออก ให้บอกสถานะ เอกสารที่ขาด และขั้นตอนถัดไปใน 3–5 บรรทัด

เปรียบเทียบก่อน/หลังด้วยคำถามเดียวกัน ข้อมูลต้องยังตรงชีท

การเขียนต้องยืนยัน

ขอเปลี่ยนเอกสาร → bot สรุปเป้าหมาย → ยืนยัน → tool เขียน → อ่านตรวจผล

ลองตอบ “ยกเลิก” ต้องไม่มีการเปลี่ยนข้อมูล ลองสั่งซ้ำขณะมีคิวต้องไม่เพิ่มซ้ำ

Memory แยกตาม Sheet + ผู้ใช้/ห้อง LINE ไม่ใช่ใช้ session ร่วมทั้งห้องเรียน

แยกข้อมูลกับคำสั่ง

Shipments = สถานะล่าสุด / Documents = เอกสาร / Events = คิวจำลอง

AI เขียน Documents และ Events ผ่าน Google Sheets tools; Simulator ส่งผลจบผ่าน Apps Script

ห้ามเปลี่ยนชื่อ tabs/headers หรือแปล status ในชีทตามภาษา UI

อ่านโครงสร้างข้อมูล

ชีทเดียวกันทั้ง LINE และเว็บ

  1. เปิด Settings บน Simulator ใส่ Sheet URL ของกลุ่ม
  2. Connect → Refresh → Start Auto Sync
  3. เช็กว่า Sheet ID ตรง Workshop Settings
  4. แก้ข้อมูลจำลองหนึ่งช่อง กด Refresh แล้วถาม LINE อีกครั้ง

สิทธิ์ edit link อย่างเดียวไม่พอ: ชีทต้องอยู่ในเจ้าของบัญชี workshop ที่ Apps Script deployment รองรับ เปิดตัวประมวลผลเพียงหนึ่งเว็บต่อชีท

ปล่อยตู้ IMP-003

  1. อ่านสถานะและเอกสารขาด
  2. บันทึก Certificate of Origin เป็น RECEIVED → ยืนยัน
  3. บันทึก Import Declaration เป็น APPROVED → ยืนยัน
  4. ปล่อยตู้ IMP-003 → ยืนยัน
  5. รอ AGV + รถออก Terminal ตรวจ DELIVERED และ Event COMPLETED

การอนุมัติเป็นเพียงข้อมูลจำลอง ไม่มีผลทางศุลกากรจริง งานใหม่จบใน CUSTOMS_RELEASE ไม่เพิ่ม GATE_OUT ซ้ำหลังจบ

ส่ง EXP-004 ถึงปลายทาง

  1. บันทึก Packing List เป็น RECEIVED → ยืนยัน
  2. รอการย้ายเข้าลานจน READY_TO_LOAD (ขอย้ายเข้าลานถ้ายังไม่มีคิว)
  3. บันทึก Export Declaration เป็น APPROVED → ยืนยัน
  4. โหลดขึ้นเรือ → ยืนยัน → รอ LOADED
  5. ออกเดินทาง → ยืนยัน → รอ IN_TRANSIT
  6. จำลองถึงปลายทาง → ยืนยัน → รอ ARRIVED

EXPORT_DEPARTURE ไม่ใช่ถึงปลายทาง ต้องมี EXPORT_ARRIVAL ห้ามสั่งขั้นถัดไปก่อนผลก่อนหน้าจบ
