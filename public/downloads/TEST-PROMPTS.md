# คำสั่งทดสอบใน LINE

ใช้ชีทสำเนาใหม่สำหรับทดสอบครบลำดับ อย่าทำซ้ำบน Shipment ที่จบแล้ว
ตอบ “ยืนยัน” หลัง bot เสนอการเขียนข้อมูลแต่ละครั้ง และรอเว็บประมวลผลก่อนขั้นถัดไป

## อ่านข้อมูล

- ตรวจ IMP-003 อยู่ที่ไหน สถานะอะไร และขาดเอกสารอะไร
- ตรวจ EXP-004 มีงานค้างอะไรบ้าง
- สรุปเอกสารที่ยัง PENDING

## Import IMP-003

1. บันทึก Certificate of Origin ของ IMP-003 เป็น RECEIVED
2. ยืนยัน
3. บันทึก Import Declaration ของ IMP-003 เป็น APPROVED
4. ยืนยัน
5. ปล่อยตู้ IMP-003
6. ยืนยัน
7. รอ animation แล้วถาม: ตรวจ IMP-003 งานปล่อยตู้เสร็จหรือยัง มี Event ค้างไหม

ผลสุดท้าย DELIVERED, Event COMPLETED; ถามปล่อยซ้ำต้องไม่เพิ่ม Event ใหม่

## Export EXP-004

1. บันทึก Packing List ของ EXP-004 เป็น RECEIVED → ยืนยัน
2. รอ EXPORT_YARD_TRANSFER จบ (หรือขอให้ย้ายเข้าลานหากยังไม่มีคิว)
3. บันทึก Export Declaration ของ EXP-004 เป็น APPROVED → ยืนยัน
4. โหลดตู้ EXP-004 ขึ้นเรือ → ยืนยัน → รอ LOADED
5. ให้เรือของ EXP-004 ออกเดินทาง → ยืนยัน → รอ IN_TRANSIT
6. จำลองว่าเรือของ EXP-004 ถึงปลายทาง → ยืนยัน → รอ ARRIVED
7. ตรวจ EXP-004 งานถึงปลายทางเสร็จหรือยัง มี Event ค้างไหม

## Guardrails

- ลองโหลดขณะ Declaration ยัง PENDING: ต้องบอกเอกสารขาด ไม่สร้างคิวผิดขั้น
- ลองสั่งซ้ำขณะมี PENDING/PROCESSING: ต้องไม่สร้างซ้ำ
- บอก “ยกเลิก” ตอนยืนยัน: ต้องไม่เขียนข้อมูล
- ตรวจคำตอบเทียบข้อมูลชีทจริง ไม่ถือคำตอบ AI เป็นหลักฐานว่าการจำลองจบ
